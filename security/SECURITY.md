# Проверка безопасности BehaviorGuard (MVP)

Область: backend (Spring Boot), ML-сервис (FastAPI), страница дашборда, SDK и тестовый банк.
Стенд: локальный dev-профиль, PostgreSQL и Redis в Docker. Проверяется только собственная система.

## Найденное и исправленное

1. **Тело запроса без ограничения (высокий риск).** Тело 20 МБ принималось и читалось целиком в память.
   Исправлено: `BodySizeLimitFilter`, лимит 1 МБ. Запрос больше лимита получает 413, при чтении без Content-Length чтение обрывается.
2. **Слабая валидация `sdkVersion` (средний риск).** Значение `0.1.0' OR 1=1` принималось и уходило в базу и журнал.
   SQL-инъекции не было (запросы параметризованы), но валидация была недостаточной. Исправлено: формат `^[0-9A-Za-z.-]{1,20}$`.
3. **Нет CSP и Referrer-Policy на странице дашборда (средний риск).** Добавлены:
   `default-src 'self'`, `script-src 'self'`, `frame-ancestors 'none'`, `Referrer-Policy: no-referrer`.
   `style-src` содержит `'unsafe-inline'`: высота столбцов графика задаётся inline-стилями. Это ослабление, отмечено ниже.

Ложные срабатывания проб, которые я разобрал:
- `/actuator/env` для администратора даёт 403, а не 401: токен валиден, эндпоинт закрыт. Ожидание в матрице исправлено.
- Проба 20 МБ получала обрыв соединения: сервер закрывал его, не дочитав тело. Это отказ, проба учитывает его так.
- Перебор паролей заблокировал аналитика на 15 минут. Блокировка сработала как задумано, dev-учётки разблокированы вручную в dev-базе.

## Закрыто в последнем раунде (все остаточные пункты)

- **Ограничение частоты в Redis** (`ratelimit/RateLimiter`): общий счётчик для всех инстансов.
  При сбое Redis вход закрыт (503), API пропускается с записью в лог.
- **IP клиента за прокси** (`ClientIpResolver`): X-Forwarded-For учитывается только от адресов из `TRUSTED_PROXIES`.
  Тесты: `ClientIpResolverTests`.
- **TLS**: HSTS отдаётся приложением и прокси. Конфиг обратного прокси: `infra/tls/nginx.conf`.
  Проверено в Docker: HTTPS проксирует на backend, HSTS и остальные заголовки передаются, HTTP перенаправляется на HTTPS,
  тело 2 МБ отсекается с 413 на периметре.
- **CSP без `unsafe-inline`**: высоты столбцов задаются через DOM, `style-src 'self'`.
- **ML-сервис с токеном**: `/v1/score` отвечает 401 без `X-BG-Service-Token`, 503 если токен не настроен. Тесты: pytest, 22 из 22.
- **Срок хранения сырых событий** (требование ТЗ): `RawEventRetention`, ежедневная очистка батчами, по умолчанию 90 дней. Тест: `RetentionAndAuditTests`.
- **Журнал аудита неизменяем в БД**: триггеры на UPDATE, DELETE и TRUNCATE (миграция V7). Тест: `RetentionAndAuditTests`.
- **Dev-учётные данные не печатаются в лог**: пишутся в `~/.behaviorguard/dev-credentials.txt` с правами 600.

Backend: 63 из 63 тестов. ML: 22 из 22. Пробы: 22 из 22. Матрица доступа: 55 из 55.

Сканирование зависимостей (финальное):
- Maven: SBOM (CycloneDX) с разрешёнными версиями, 120 компонентов, OSV-scanner: уязвимостей нет.
- npm, продакшен-зависимости: `npm audit --omit=dev` — 0 уязвимостей (тестовый банк и SDK).
- Python (ML-сервис): `pip-audit` — уязвимостей нет; транзитивные `anyio`, `certifi`, `idna` зафиксированы в `requirements.txt`.
- Остаётся одна уязвимость средней степени (GHSA-gcqx-w48m-w2h4, `deepmerge` 4.3.1): транзитивная зависимость Jest,
  только для тестов, в поставку не входит, исправленной версии нет. Риск принят.
- Исправлено: `glob` и `minimatch` в npm через `overrides` (без смены мажорной версии Expo), обновлены `anyio`, `certifi`, `idna`.

## Закрыто в этом раунде

- **Ограничение частоты.** Вход: 10 попыток в минуту с одного IP (`RATE_LOGIN_PER_MINUTE`).
  API интеграций: 60 000 запросов в минуту на пару «организация + тип ключа» (`RATE_API_PER_MINUTE`).
  Сверх лимита ответ 429 с `Retry-After`. Тесты: `RateLimitTests`.
- **Токен дашборда в httpOnly-cookie.** `bg_admin`: HttpOnly, SameSite=Strict, Path=/, срок 8 часов.
  Из JavaScript cookie недоступна (проверено в браузере), в `sessionStorage` и `localStorage` ничего не хранится.
  Вход восстанавливается через `GET /api/v1/auth/me`. Тесты: `CookieSessionTests`.
- **CSRF.** Изменяющие запросы с cookie без заголовка `X-BG-Requested` получают 403.
  Подделка с чужого сайта не может добавить этот заголовок без CORS-предзапроса, а CORS у нас закрыт.

## Остаточные риски (не закрыты, важны для пилота)

1. **Ограничение частоты работает в памяти одного экземпляра.** При нескольких инстансах лимит нужно вынести в Redis.
   Ключ входа — IP из `getRemoteAddr()`: за балансировщиком нужно доверять `X-Forwarded-For` только от него.
2. **Перебор по множеству логинов с разных IP** остаётся возможен в рамках лимита на IP. Блокировка по аккаунту работает.
3. **`style-src 'unsafe-inline'`.** Ослабляет CSP. Исправимо, если переписать высоту столбцов через CSSOM.
4. **ML-сервис без аутентификации.** Слушает 127.0.0.1 по умолчанию, но в продакшене должен быть доступен только из внутренней сети
   с mTLS или токеном сервис-к-сервису.
5. **Пароли и ключи dev-профиля печатаются в лог.** Относится только к dev. Для продакшена этого кода быть не должно,
   но стоит убедиться при выкладке.
6. **TLS не настроен.** Локально работает по HTTP. Для пилота нужен TLS на входе (балансировщик или прокси), HSTS на нём же.
7. **Журнал аудита не защищён от модификации на уровне БД.** Приложение не меняет записи, но DBA может. Для банка
   нужны права только на INSERT и отдельный контроль доступа к таблице.
8. **Сырые события хранятся без срока жизни.** ТЗ требует ограничения сроков хранения сырых событий; реализации пока нет.
9. **Тестовый банк хранит ключ SDK в `.env.local`.** Файл в `.gitignore`. Публичный ключ SDK по замыслу виден в приложении.
