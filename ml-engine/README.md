# ML Engine (BehaviorGuard)

Сервис скоринга: отклонение сессии от личного профиля пользователя и Isolation Forest.
Сервис без состояния: профили хранятся в PostgreSQL у backend и передаются в каждом запросе.

## Запуск

```bash
cd ml-engine
python3.12 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
./.venv/bin/python -m training.train      # обучение (синтетика), пишет models/isolation_forest_v0.1.joblib
./.venv/bin/python -m training.evaluate   # оценка на независимых пользователях, пишет models/evaluation_v0.1.json
./.venv/bin/python -m pytest -q
./.venv/bin/uvicorn app.main:app --port 8000
```

Python 3.12: wheel-пакеты scikit-learn для 3.14 на момент сборки ставились не у всех.

## API

`POST /v1/score`

```json
{
  "features": {"tap_duration_ms": 120, "key_interval_ms": 230, "chars_per_minute": 200, "...": null},
  "profile": {
    "session_count": 7,
    "stats": {"key_interval_ms": {"mean": 228, "std": 11, "n": 7}}
  }
}
```

Ответ: `risk_score` (0–100), `anomaly_score`, `profile_score`, `reasons`, `z_scores`, `model_version`.
Если признаков слишком мало (меньше половины), ответ `422`: backend возвращает `UNKNOWN`, а не низкий риск.
Неизвестные признаки и нечисловые значения отклоняются. Тело ошибки не содержит входных значений.

`GET /health` — статус и версия модели.

## Признаки (контракт с backend)

Порядок и имена совпадают с `FeatureExtractor.java`. Меняются только вместе с версией модели.

| Признак | Источник (событие, поле) |
|---|---|
| tap_duration_ms | TAP.durationMs |
| tap_interval_ms | TAP.intervalMs |
| swipe_speed_px_s | SWIPE.avgSpeedPxS |
| scroll_speed_px_s | SCROLL.avgSpeedPxS |
| key_interval_ms | TEXT_INPUT.keyIntervalAvgMs, взвешенно по keyCount |
| chars_per_minute | TEXT_INPUT.charsPerMinute, взвешенно по keyCount |
| backspace_ratio | сумма backspaceCount / сумма keyCount (если набрано ≥ 10) |
| screen_dwell_ms | SCREEN_VIEW.dwellMs |

## Как считается балл

1. **z-отклонения.** Для каждого признака `z = (x − mean) / sd`. Нижняя граница `sd = 5% от mean`, чтобы почти постоянный профиль не давал огромных z. Признаки с `n < 3` пропускаются.
2. **Профиль.** `0.5 · min(1, max|z|/4) + 0.5 · min(1, mean|z|/3)`. Смесь максимума и среднего: одно сильное отклонение не растворяется среди нормальных. Выбрано на валидационном seed.
3. **Isolation Forest** по z-вектору, `iso = sigmoid(−10 · decision)`.
4. **Итог.** `100 · (0.6 · iso + 0.4 · profile)`.
5. **Экстремум.** Если какой-либо признак отклонился на 6σ и больше, итог не ниже 70 (HIGH). Причина: Isolation Forest слабо реагирует на экстремум по одному признаку при нормальных остальных. Порог 6σ выбран статистически, а не по метрикам.
6. **Причины.** Признаки с |z| ≥ 3 переводятся в коды (`TYPING_PATTERN_ANOMALY` и т. д.). Если причин нет, но `iso ≥ 0.7`, то `MULTIVARIATE_ANOMALY`.

Пороги уровней (LOW < 40 ≤ MEDIUM < 70 ≤ HIGH) и рекомендации задаются в backend (`RiskPolicy.java`).

## Качество на синтетике

**Важно:** данные синтетические, это не реальные пользователи и не реальные мошенники. Цифры показывают, что конвейер работает, но не говорят о качестве на банковских данных. Для пилота нужны подтверждённые случаи (раздел 6 ТЗ).

Оценка на 300 отдельных пользователях (другой seed, не из обучения): по 20 нормальных и 20 аномальных сессий на пользователя, всего 12 000 сессий (6 000 нормальных и 6 000 аномальных):

| Метрика | Значение |
|---|---|
| ROC-AUC | 0.956 |
| PR-AUC | 0.958 |
| HIGH (порог 70): precision / recall / FPR | 0.976 / 0.636 / 0.015 |
| MEDIUM (порог 40): precision / recall / FPR | 0.748 / 0.965 / 0.326 |
| Задержка скоринга, медиана / p95 | 4.5 мс / 4.6 мс |

Recall при пороге HIGH по типам аномалий:

| Тип | Recall |
|---|---|
| Другой человек (impostor) | 0.58 |
| Быстрый набор (typing) | 0.30 |
| Спешка (rushed) | 0.70 |
| Скрипт (scripted) | 0.97 |

### Что это значит

- **Быстрый набор ловится слабо.** Сдвиг признаков умеренный (в 1.8 раза), и при пороге HIGH его видно лишь в 30% случаев. На уровне MEDIUM его ловят чаще, но FPR там высокий.
- **MEDIUM не основание для действий.** При FPR 33% это сигнал «наблюдать», а не «требовать подтверждения».
- **FPR при HIGH вырос до 1.5%** после правила 6σ. Причина: профиль строится по 8 сессиям, оценка дисперсии по малой выборке бывает занижена, и норма иногда выглядит как 6σ. Это ограничение, а не причина подгонять порог. Смягчаем увеличением минимума сессий для READY или нижней границы sd.
- **Выбор формулы и правила 6σ сделаны без тестового набора.** Формула профиля выбрана на валидационном seed 7 (`training/tune_profile.py`). Метрики в таблице — на тестовом seed 2024.

Полный отчёт: `models/evaluation_v0.1.json`.
